# Changelog

Every release of this template, newest first, a line each. Each release is
a git tag on the template's `main`, `v` and its version (`v0.9.0`), and its
notes are a file of their own, `.superforge/releases/<version>.md`.
`.superforge/superforge.json` says which release a copy is on.

`workbench/updating.md` says how a release is written and how a copy takes
one: it reads only the releases after the copy's, each from its own file.
Until 0.8.0 every release's notes were in this file, under its heading;
0.9.0 moved each to its own.

- [0.33.0](.superforge/releases/0.33.0.md) (2026-11-25): Foundation's license is the Superforge Foundation License, not MIT: a business builds its own software on its own copy, may have anyone it hires work on it, and runs and sells what it builds; nobody passes Foundation on as a template or builds on it for someone else from a copy of their own; the credit in every page's source is a term; `THIRD-PARTY-NOTICES.md` lists what came from others. Releases before it stay MIT.
- [0.32.0](.superforge/releases/0.32.0.md) (2026-11-25): a copy's own goes in files of its own: the team and its roles in `auth/app.ts`, the Railway project's names, region, domains and variables in `.railway/app.ts`, the site's title, whom it remembers, how long things are kept and Your files' limits in `utilities/settings/app.ts`, and its events, queues and webhook sources beside the template's, so no release meets them again; a copy moves its own there once, in this update.
- [0.31.0](.superforge/releases/0.31.0.md) (2026-11-25): `/api/visits` has a ceiling: each network may send 20,000 events a day, a batch counting as its events or its kilobytes, the team's and bots' uncounted, and 429 `too-many` past it; a visit holds at most 5,000 events; and `countAttempt` takes an `amount`.
- [0.30.0](.superforge/releases/0.30.0.md) (2026-11-25): a row of the team is a slug with an address: a new address ends every way in the old one had (sessions, API tokens and Claude's connections), a new slug always gets a row of its own, an address is unique among the active team only, and a row comes back only once Infra has ended Claude's connections as it.
- [0.29.0](.superforge/releases/0.29.0.md) (2026-11-24): `@superforge/infra` 0.5.0, the surface it keeps at 1.0.0: it brings its own zod, so the app's can move on without it, exports fewer names, and reads Infra's answers tolerantly, so a new sending limit or scope doesn't break an app; Claude's scopes are built with the app's own zod, `z.enum(AGENT_SCOPES)`.
- [0.28.1](.superforge/releases/0.28.1.md) (2026-11-24): `/login`, opened logged in, no longer logs a hydration error: `useSession()` answers `loading` on any render that hydrates a page, whatever the browser already knows, so a page hydrates as the visitor's the prerender drew.
- [0.28.0](.superforge/releases/0.28.0.md) (2026-11-24): the admin on Skylevel's frame: a sidebar with who's logged in at its foot and the gear to Settings, an Overview that says the dashboard is the business's to build, Settings with the team, read-only, an `app.ts` for the app's own sections and parts of Settings, and no Workflows or Team screen.
- [0.27.0](.superforge/releases/0.27.0.md) (2026-11-24): the toolbar shows only where Infra keeps what's filed, never on a dev server's stand-in, which only logs a comment, nor with a key Infra refuses, by asking `GET /api/comments/board` first; and every route can tell which Infra the server calls (`context.var.infra_using`).
- [0.26.0](.superforge/releases/0.26.0.md) (2026-11-24): the `main` ruleset is in the codebase, `.github/rulesets/main.json`, and `pnpm github:ruleset` puts it on GitHub, an agent's step, no longer the owner's by hand; on a GitHub plan with no rulesets for a private repository it says so and passes.
- [0.25.1](.superforge/releases/0.25.1.md) (2026-11-24): logging out takes the page with it: the admin draws "Log in to the admin" at once, without a refresh, the toolbar goes, and nothing asked for after the logout is answered 401.
- [0.25.0](.superforge/releases/0.25.0.md) (2026-11-24): the code fixes ahead of 1.0.0: a megabyte limit on every body, another origin's requests refused by what the browser says, security headers on every answer, logins counted per network, Claude's token held to its scopes and answered 503 when it can't be checked, a failed query's values kept out of the logs, and `@superforge/infra` 0.4.0.
- [0.24.0](.superforge/releases/0.24.0.md) (2026-11-24): the cleanup ahead of 1.0.0: `tell-team-of-sign-up` and `user-signed-up` gone, with `jose` and exports nothing used, checks on the analytics' fixed lists, `files.size` a bigint and a folder unable to go from under its files, API tokens' scopes the app's own list, 30 seconds for a deploy's stop, and the local Postgres made again after a major version change.
- [0.23.0](.superforge/releases/0.23.0.md) (2026-11-24): a copy starts in a private repository of its own, an update follows the latest release's procedure and stops at a release flagged Deploy, a rule for `package.json`, `pnpm check` fails on a schema change no migration holds, `SECURITY.md`, the docs put right, and unused primitives gone.

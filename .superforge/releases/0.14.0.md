# 0.14.0 (2026-11-23)

The app calls Superforge Infra through **`@superforge/infra`**, an npm
package every Foundation and Skylevel app shares, in place of the client
it carried in `source/backend/infra/`. A change to how Infra is called is
a new version of the package from now on, which a copy takes by bumping
one dependency, rather than a template release. And when login breaks,
**the login page tells the business's own people why**, in Infra's
words, instead of only "Login isn't working right now".

- **The package**, machinery. `package.json` depends on
  `@superforge/infra` (`^0.1.1`). `source/backend/infra/`'s
  `agents.ts`, `answers.ts`, `choose.ts`, `client.ts`, `comments.ts`,
  `stand-in.ts` and their tests are gone: they're the package's now.
  `index.ts` is the app's one seam to it: `appInfra()`, and what the rest
  of the app imports of the package (`Infra` and its results,
  `standInInfra`, `standInAgentToken`, `requestOrigin`, `infraClient`).
  The imports that named the old files (`@/backend/infra/stand-in`,
  `@/backend/infra/client`, `../infra/agents`) import from
  `@/backend/infra`. A copy's own code that imports one of the old files
  does the same.
- **Infra knows which version an app is on**, machinery. Every call the
  package makes carries `Infra-Client: @superforge/infra/<version>`, so
  Infra can tell an app it's out of date. Nothing in the app sets it.
- **Every refusal says why**, machinery. Infra answers every error with
  `message`, what went wrong and what fixes it, and the package carries it
  on every refusal, `unavailable` included, with its own words when it
  couldn't ask (no `INFRA_SECRET_KEY` in a build, a test key in its place,
  an Infra that didn't answer, an error it doesn't know, like a call
  Infra retired). It logs every refusal with them (`Infra refused a
  call`). A copy's own code that makes a refusal by hand, like a test's
  stub of Infra, gives it a `message`.
- **The team sees why on the login page**, machinery. When the email
  didn't go out or Infra couldn't be asked, `/api/auth/start` and
  `/api/auth/verify` answer a new optional field, `cause`, Infra's words,
  to one of the business's own people (`internal_users`, by the address
  they typed) and to anyone on a dev server; a visitor still gets the
  plain message alone (`forTheTeam` in `backend/auth/routes.ts`,
  `cause` in `utilities/schemas/failures.ts`). The login form and the
  login page show it under the plain message, as "For the team: …"
  (`TeamCause` in `frontend/components/site/login-form.tsx`).
- **`AsyncOperation` is `AsyncOperationResult`**, machinery, to match
  `OperationResult`: it's the type of what an async operation returns,
  not the operation. `source/globals.d.ts` declares it, and every file
  that used it says the new name. **A copy renames its own uses** the
  same way, everywhere its code says `AsyncOperation<`.

How to tell a copy already has it: `package.json` has
`@superforge/infra`, `source/backend/infra/` holds only `index.ts` and
`README.md`, and `source/globals.d.ts` declares `AsyncOperationResult`.

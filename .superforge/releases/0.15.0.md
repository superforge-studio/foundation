# 0.15.0 (2026-11-23)

API tokens. One of the business's own makes one on their account page for
what can't log in through a browser, as Claude does with one click on the
Allow page: a script, a scheduled job, another platform's agent. It calls
the app's API under `/api`, and its MCP at `/admin/mcp`, as the person who
made it, with what they let it do, until they revoke it.

- **The table**, machinery. **Schema**: `auth.api_tokens`
  (`source/database/schema.ts`), a row per token: whose it is (`user_id`,
  deleted with them), its `name`, the SHA-256 of the token
  (`token_hash`), never the token, its last four characters (`preview`),
  its `scopes` (`read`, and `act`, as Claude's are, with a check that
  they're only those and at least one), when it runs out (`expires_at`,
  null for one that lasts until it's revoked), when it was last used
  (`last_used_at`) and when it was made. `pnpm database:generate` writes
  the copy's migration from it, with nothing to write by hand.
- **The tokens**, machinery: `source/backend/auth/api-tokens.ts` makes,
  lists, revokes and checks them. A token is `api_` and 43 letters and
  digits (`tokens.ts`'s `randomCharacters`), shown once as it's made. It
  lasts until it's revoked unless it's given 30, 90 or 365 days
  (`API_TOKEN_LIFETIMES`, `utilities/schemas/api-tokens.ts`). Revoking it
  deletes its row, so the next request with it is refused. A token in use
  notes when it was last used, at most once a minute.
- **Logging in with one**, machinery: `source/backend/auth/logged-in.ts`
  takes `Authorization: Bearer api_…` beside Claude's token, telling them
  apart by the prefix, so an API token never goes to Infra. It logs in its
  person only while they're one of the business's own, as `access.ts`
  lists them, never anyone external, so it stops working the moment
  they're taken off the list. `context.var.scopes` holds its scopes, as
  it does Claude's: with only `read`, it makes `GET` requests alone (403
  `read-only`), and `inBrowser` refuses it (403 `browser-only`), so a
  token can't make, list or revoke tokens, or change who logs in.
  `context.var.logged_in_with` has a third value, `"token"`, and
  `context.var.session` is `API_TOKEN_SESSION` for one. **A copy's own
  code that branches on `logged_in_with`** handles `"token"` too: say so
  to the owner if it treats anything but `"session"` as Claude.
- **The routes**, machinery: `GET`, `POST /api/account/tokens` and
  `DELETE /api/account/tokens/:id` (`source/backend/account/routes.ts`),
  for the business's own (`internalOnly`), in a browser (`inBrowser`).
  Making one answers `{ token, api_token }`, the only answer the token is
  ever in; listing never has the token or its hash.
- **The account page**, machinery: an API tokens section under Claude's
  connections, for the business's own
  (`source/frontend/components/dashboard/api-tokens.tsx`, its queries in
  `queries/account.ts`): each token by its name, `api_…` and its last
  characters, whether it reads only, when it was last used, made and runs
  out, with Revoke, asked once more in place; making one by its name,
  read only or read and act, and when it runs out; and the token just
  made, with Copy, shown until Done. `words.ts` has `day()`, a date
  without its time. A copy that moved its account page's sections puts
  this one where its own page has room.
- **The upgrade test's sample rows**, machinery:
  `source/database/tests/support/fill.ts` gives a list column whose check
  names what it may hold (`<@ array[…]`) one of those values, as it does a
  text column's, so later upgrade tests fill `api_tokens`.
- **The seed**, machinery: `seed/users.ts`'s `seedApiTokens`, the first
  internal person's three sample tokens, in use, never used, and run out,
  each of a token too short to be one, so nothing logs in with them.
- **The docs**, machinery: `CLAUDE.md`'s architecture list,
  `workbench/writing-code.md` ("Headless", "Data") and
  `source/backend/mcp/README.md`, "Without a browser: an API token".

How to tell a copy already has it: `source/backend/auth/api-tokens.ts`
exists, and `schema.ts` declares `api_tokens`.

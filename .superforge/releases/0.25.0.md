# 0.25.0 (2026-11-24)

The code fixes ahead of 1.0.0, from the review of 0.22.0: a limit on every
request's body, a check for another origin's requests that looks at the
browser rather than the body, security headers on every answer, logins
counted per network, Claude's token held closer to what it was given, a
failed query's values kept out of the logs, and smaller fixes in files,
webhooks, workflows, analytics and the tests. And `@superforge/infra`
0.4.0. A minor, since several routes answer differently. No flags: no
schema change, no variable, nothing for the owner to do.

## `@superforge/infra` 0.4.0 (`package.json`), machinery

The package's release of the same review. The app's code needs nothing
for its changed error shape, since it reads only `ok`. With it:

- **`pnpm build` is `NODE_ENV=production vite build`**, so a service whose
  `NODE_ENV` says `development` still builds a server that takes only a
  secret key, never the stand-in a dev server logs in with.
- **A login code is 4 to 12 digits, and a link's token 20 to 200
  characters of base64url** (`login_code`, `login_token`,
  `source/utilities/schemas/auth.ts`), so Infra, which checks them, is the
  one to say no if their length ever changes.
- **The OAuth test uses `example.com`** (`backend/agents/tests/agents.test.ts`).
- **Claude's token expires on time**: the package gives a clock five
  seconds' leeway, so a test's "expired" token is one that ran out a
  minute ago.

How to tell a copy already has it: `package.json` names
`"@superforge/infra": "^0.4.0"` and its `build` starts `NODE_ENV=production`.

## The API's limits and its check for other sites (`source/backend/index.ts`), machinery

- **No body over a megabyte** (`API_BODY_LIMIT`), whoever sends it: 413
  `too-large` before it's read, in the one shape, where only four routes
  had a limit before. Webhooks keep their 2 MB, mounted ahead of it. The
  app's MCP takes the same megabyte, and `/oauth/*` 16 KB.
- **A dev server's upload (`PUT /api/files/uploads/:file_id`) checks who's
  asking and that the upload is under way before it reads a byte**, then
  takes up to 100 MB (`source/backend/files/routes.ts`). Before, anyone
  logged out could make the server hold 100 MB before being told 401.
- **Another origin's request is refused by what the browser says, not by
  its body** (`refuseOtherSites`, replacing Hono's `csrf()`): any method
  but `GET`, `HEAD` and `OPTIONS` is 403 `forbidden` when its `Origin`
  isn't this host, or its `Sec-Fetch-Site` is `cross-site` or `same-site`.
  So a page on a sibling subdomain, whose requests carry the
  `SameSite=Lax` cookie, can no longer send the bodiless `POST`s (log out,
  restore from Trash, make a link, retry a run) that the old check let
  through for having no `Content-Type`. A script or curl sends neither
  header, and gets through as before. `takesFormsFromOtherSites`
  (`backend/app.ts`) still opens a route of the app's.
- **A copy with routes of its own** that another origin of the business's
  calls from a browser (a form on its marketing site posting here) now
  has them refused whatever their body: name each in
  `takesFormsFromOtherSites`, and check who's asking there. A copy that
  takes a body over a megabyte on a route of its own mounts it ahead of
  the limit, as webhooks are, or exempts it in `takesLargerBody`
  (`index.ts`) and sets its own `bodyLimit` after its checks.
- **A Hono refusal other than a body that isn't JSON** is answered with
  its own status as `refused`, no longer every 403 as a cross-site form
  (`answerUnexpected`, `backend/failures.ts`).

How to tell a copy already has it: `grep -n refuseOtherSites source/backend/index.ts`.

## Security headers (`source/node.ts`), machinery

Every answer of a build, files, pages and the API alike, carries
`Content-Security-Policy: frame-ancestors 'none'`, `X-Frame-Options:
DENY`, `X-Content-Type-Options: nosniff` and `Referrer-Policy:
strict-origin-when-cross-origin`, and `Strict-Transport-Security:
max-age=31536000` on any host but this computer's. An answer that sets
its own `Content-Security-Policy` keeps it. No Content-Security-Policy
limits scripts or styles yet: that's the app's to add once it's tuned to
what its pages load. The smoke test checks them on a prerendered page, a
page drawn on request, a built file and the API
(`workbench/scripts/smoke-test.mjs`). **A copy that frames its own pages
in another of its sites** loosens `frame-ancestors` and drops
`X-Frame-Options` in `securityHeaders`.

How to tell a copy already has it: `grep -n securityHeaders source/node.ts`.

## Logging in (`source/backend/auth/`), machinery

- **`/auth/start` is counted per network, 20 an hour, listed or not**
  (`countAttempt`, the rate limiter's first caller), past which it's 429
  `too-many` with a `Retry-After`. So a list of addresses can't be walked
  to learn who's on the team. An unlisted address is still told it isn't
  (403 `not-listed`): whether to answer every address alike is a decision
  left open (`auth/README.md`, "Decisions left open").
- **The login page says what `not-listed` and `too-many` mean**
  (`whatWentWrong`, `frontend/components/site/login-form.tsx`), in the
  API's words, where it said "Login isn't working right now" to anyone
  not on the team. Starting point: a copy that rewrote the form's words
  keeps its own and adds the two cases.
- **Claude's token, and an API token, that names neither `read` nor
  `act` may do nothing**: Claude's is refused as nobody's (`agentUser`,
  `auth/agents.ts`), and the levels a token gets are `none` without one
  (`permissionsFor`, `mayDo`, `auth/logged-in.ts`). Before, such a token
  read everything its person could. Infra issues none today.
- **Claude's token that can't be checked is 503 `unavailable`**, with a
  `Retry-After`, never 401, when Infra's public keys can't be fetched:
  from `loggedIn`, `permitted` and `maybeLoggedIn`, and from the MCP, so
  Claude tries again rather than dropping a good connection. A bearer
  that isn't a JWT's three parts is nobody's before Infra is asked.
  **The typed client's answer for `GET /api/auth/session` now includes
  the 503**, so code that reads `.json()` without checking the status
  stops typechecking: check `response.ok` first, as
  `frontend/queries/auth.ts` does.
- **`/api/auth/session` answers `scopes`** beside `user` and
  `permissions`: what the request was let do, null for a visitor. The
  MCP reads it.
- **A new API token lasts 90 days unless its maker chooses otherwise**
  (`frontend/components/dashboard/api-tokens.tsx`); "Never" is still a
  choice. Starting point.

## Claude's Allow page and the MCP (`source/backend/agents/`, `source/backend/mcp/`), machinery

- **The Allow route only allows a request for the app's own MCP**, at
  its origin and `/admin/mcp`: one for any other address on the origin,
  like a customers' MCP a copy adds at `/mcp`, is 404 to the page and the
  allow route alike. **A copy with an MCP of its own** gives its people
  an Allow of their own for it.
- **Where Infra sends the browser back must be a web address**, or the
  route answers 502 `bad-redirect`.
- **`list_routes` offers only what a token can call**: no `inBrowser`
  route, and none of the routes anyone may call without logging in. And
  **`call_api` refuses anything but a `GET` itself** for a connection
  that may only read, so it can't start a teammate's login.
- **The MCP and `/oauth/*` fail in the API's one shape**: the MCP's 401
  is `{ error: { reason: "logged-out", message } }`, an unknown
  `/oauth/x` is `{ error: { reason: "not-found", … } }`, and both apps
  answer a miss and a throw with the API's own handlers. OAuth's own
  calls keep the answers RFC 6749 gives them, which Infra makes.
- **A page sent a `POST`** is 405 in the one shape too
  (`refuseForPage`, `source/server.ts`), no longer plain text.

## A failed query's values stay out of the logs (`source/utilities/tracing.ts`), machinery

Drizzle's error for a failed query carries every value it was sent, an
email address, a token's hash, a webhook's whole body. `withoutValues`
turns one into its statement, Postgres's message and its code, and
`answerUnexpected` logs that and `recordError` marks the span with it,
so neither Railway's logs nor its traces hold the values. A failed step's
error, as the Workflows API answers it, drops what follows `params:`
(`backend/workflows/runs.ts`); DBOS still keeps it whole in its own
tables.

## Strings Postgres can't keep (`source/utilities/schemas/text.ts`), machinery

`storable` refuses a U+0000, or half of an emoji, which `text` and
`jsonb` refuse, as a 400 the sender drops, rather than a 500 the page
sends again forever: on an event's properties, a page's path and a
file's or a folder's name. The pages' script cuts free text without
splitting an emoji, and drops any U+0000
(`frontend/visitors/describe.ts`'s `scrub`). A webhook's body with a NUL
character is 400 `unreadable`, kept nowhere.

## Smaller fixes, machinery

- **Two folders moved into each other at once** can no longer end up
  inside each other: a folder's change takes an advisory lock first
  (`changeFolder`, `backend/files/change.ts`, lock 1691).
- **Emptying Trash deletes at most 5,000 files a run**, a thousand rows
  a delete, so it never names more ids than Postgres takes; the rest
  waits an hour (`emptyExpired`, `backend/files/trash.ts`).
- **An empty file opens in a dev server** as an empty body, not a 500
  (`source/database/storage/folder.ts`).
- **The Workflows screen keeps listing past a thousand quiet runs**: DBOS
  is asked for the runs of the workflows that aren't quiet, by name, and
  for every failed run, beside the scan of the newest
  (`shownRunIds`, `backend/workflows/engine.ts`).
- **Webhooks are checked over the body's bytes** (`delivery.bytes`), so
  a body that isn't valid UTF-8, or starts with a byte-order mark, can
  verify, and **a Standard Webhooks secret whose key is under 24 bytes is
  `unconfigured`** (503), not a key anyone could sign with
  (`backend/webhooks/standard.ts`). **A copy with a source of its own**
  that checks a signature over `delivery.body` checks it over
  `delivery.bytes` instead; `Delivery` has both.
- **The location database's download is capped**: 200 MB, and 400 MB
  unzipped, past which it's refused and logged
  (`backend/visits/location.ts`).
- **The test that every route says who may call it** now requires a
  route behind `maybeLoggedIn` to be listed in `ANYONE` with why
  (`GET /api/auth/session` and `POST /api/visits` are), and fails on a
  route added with `.all()` (`backend/tests/routes.test.ts`). **A copy
  with a `maybeLoggedIn` route of its own** lists it in `APP_ANYONE`
  (`backend/tests/support/app.ts`).
- **The upgrade test takes samples of the app's own**
  (`APP_SAMPLES`, a new `source/database/tests/support/app.ts`), keyed by
  `table.column` or a type, for a column `fill()` has no sample for or a
  check it can't read, so a copy never edits `fill.ts`.
- **The comments and READMEs say what's true**: tracing's redaction list
  covers what the server answers, not its `fetch` calls
  (`source/tracing.ts`); Railway's traces hold each request's address and
  `User-Agent` (`backend/visits/README.md`); `textList()` and storage's
  `text()` are kept for copies.

## The template's home page, in a build (`source/frontend/routes/index.tsx`), template only

A build's home page now says only that the site is running; the line
map, which named the stack, its parts and its paths, shows in a dev
server alone. START-HERE.md replaces the page in a copy, so a copy
that has a home page of its own has nothing to take.

## For Skylevel

Its own `logged-in.ts`, `mcp/index.ts`, `index.ts` and `server.ts` differ
from these: the merge brings `uncheckable` and the 503, `scopes` on the
session, the MCP's `scopes` and `list_routes` changes (its MCP reads
`person`), `refuseOtherSites` in place of `csrf()`, the body limit, and

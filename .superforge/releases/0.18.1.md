# 0.18.1 (2026-11-23)

The smoke test no longer fails at random, about one CI run in five, with
"The server sent its collector no traces". It took pnpm's exit for the
server's, and on CI pnpm exits first. Nothing in the app changes.

- **Waiting for the server to stop**, machinery:
  `workbench/scripts/smoke-test.mjs`'s `stopServer()` still sends SIGTERM
  to the whole process group, `pnpm start` and the Node server it started.
  It now waits until every process in that group has exited, where it used
  to wait for pnpm alone. On CI, `pnpm/action-setup` installs pnpm v11, which
  runs the `pnpm@10.17.0` that `package.json` names as a child and relays
  signals to it. So v10 is sent SIGTERM twice, and on the second, the
  signal-exit that v10 loads kills it at once. pnpm then exited while the
  server was still sending its last spans: the smoke test found none, then
  dropped the database under the server, which logged `terminating
  connection due to administrator command`. The check itself is unchanged:
  a server that doesn't send its last spans as it stops still fails it.

No flags: no schema, no variable, nothing for the owner to do.

**How to tell a copy already has it**: `smoke-test.mjs` has a
`groupRunning` function.

# 0.36.0 (2026-11-25)

Railway's own address for the app is optional in `.railway/app.ts`. A new
copy still needs one: the first apply makes the service with it, since
Railway's CDN needs a public domain to start on. After that, nothing
needs it once the app has a domain of its own, and the file can't keep it
anyway: if it's deleted from Railway, the plan doesn't notice. Until now
`address` was required, so a copy whose address had gone had to write one
Railway never serves. A minor, since what a copy may write in its own
`.railway/app.ts` changed. A copy that sets `address` gets exactly what it
had: `railway config plan` shows no change. No schema change and no
variable.

**Owner**: nothing to decide. The agent checks the copy's address (below);
the owner reviews the PR as with any update.

## Railway's address (`.railway/railway.ts`, `.railway/app.ts`), machinery

- **`AppRailway`'s `address` is optional.** `railway.ts` declares the
  app's `serviceDomains` only when `.railway/app.ts` gives one, and its
  `customDomains` from `domains`, as before.
- **A new copy keeps it**: the first apply needs a public domain, so
  `START-HERE.md` and `workbench/commit-and-deploy.md`'s "Setting up
  Railway" still name one, and an apply with neither an address nor a
  domain fails, saying so.

**Checking a copy's own, in this update**: `.railway/app.ts` is the
copy's own, so the update doesn't change it. If the copy has a custom
domain, see whether Railway still serves its address (the service's
Settings → Networking, or `railway domain` with the service). If it
doesn't, and `.railway/app.ts` names one anyway, take `address` out. If
the copy edited `.railway/railway.ts` by hand to leave the address out,
put the template's file back. A copy that edited the file by hand to give
the service a name other than `app` renames the service in Railway first,
then takes the template's file: the plan matches a service by its name,
so changing the name in the file alone would make a new service.

## The guides

`workbench/commit-and-deploy.md`'s "Domains" says when `address` may be
left out, and "Setting up Railway" that the first apply needs it.

How to tell a copy already has it: `.railway/railway.ts`'s `AppRailway`
has `address?: string`.

# 0.27.0 (2026-11-24)

The toolbar shows only where Infra keeps what's filed. It used to show to
anyone on the team logged in on a computer with a mouse, whatever Infra
was, so on a dev server with no test key, which runs on Infra's stand-in,
a comment said Saved and was only printed in the server's log. Now the
toolbar asks the server first where a comment would go, and shows only
when the server calls Infra itself with a key Infra takes. A minor, since
it changes when the toolbar shows. No flags.

## Where a comment goes (`source/backend/comments/`), machinery

- **`GET /api/comments/board`**, for anyone on the team who's logged in
  (`loggedIn`), answers `{ board: { project: { id, name }, mode } }`, the
  project on Infra the server's key is for, or `{ board: null, why: {
  reason, message } }` when nothing would keep a comment: `stand-in`, a
  dev server with no test key it can use, or `unavailable`, with no secret
  key in a build, a key Infra refuses, like a test key that expired, or an
  Infra that doesn't answer, in Infra's words or the package's
  (`routes.ts`).
- **The server asks Infra which project its key is for once**
  (`project()`, `GET /v1/project`), and again a minute after a failure
  (`board.ts`'s `findBoard`).
- `POST /api/comments` is unchanged: the stand-in still takes a comment,
  as Infra would, for the tests and a script.
- Tested in `tests/board.test.ts`.

## Which Infra the server calls (`source/backend/infra/index.ts`), machinery

- **`appInfraUsing()`** says which Infra `appInfra()` is, as the package's
  `chooseInfra` chose it: `"secret key"`, `"test key"`, `"stand-in"` or
  `"nothing"`. Every route reads it from `context.var.infra_using`
  (`source/backend/context.ts`, `serverVariables()` in
  `source/backend/index.ts`).
- **`testApi()` says `"stand-in"`**, as its Infra is, unless a test gives
  its own (`source/backend/tests/support/api.ts`). **A copy's own test
  that hands `testApi()` a fake of Infra itself** and needs the board gives
  `infra_using` too: `testApi({ infra, infra_using: "test key" })`.
- The seam passes on the package's `InfraProject` and `InfraUnavailable`
  again, which `board.ts` uses.

## The toolbar (`source/frontend/components/toolbar/toolbar.tsx`), machinery

- **`Toolbar()` asks `commentBoardQuery`** (`source/frontend/queries/comments.ts`)
  once someone's logged in on a computer with a mouse, and draws the
  toolbar only with a board. It asks once a page, so the toolbar never
  goes from under a comment being written, and the next page loaded asks
  again. A copy that changed `Toolbar()` keeps its changes and adds the
  board's check.
- **A dev server with no test key has no toolbar now.** To see it, put
  the project's test key in the checkout's `.env` as `INFRA_TEST_KEY`
  (the Superforge MCP's `create_test_key` makes one), and restart the dev
  server.

## The docs, machinery

The toolbar's README ("Only where Infra keeps what's filed"),
`source/backend/infra/README.md` ("Comments" and "Keys"), `CLAUDE.md`'s
`toolbar/`, `index.ts`, `comments/` and `infra/`, `workbench/writing-code.md`
("Local development"), `.env.example` and `README.md` ("Superforge Infra")
say when the toolbar shows.

How to tell a copy already has it: `source/backend/comments/board.ts`
exists, and `grep infra_using source/backend/context.ts` finds it.

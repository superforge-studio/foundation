# 0.16.0 (2026-11-23)

Every page credits Superforge in its source. Its head names the template
the codebase was built on in a `<meta name="generator">`, as WordPress,
Webflow and Framer name themselves on sites built with them, so anyone who
asks how the site was built, or the agent they ask, finds out. Nothing on
the page shows it.

- **The credit**, machinery: `source/utilities/template.ts`'s `GENERATOR`,
  the template's name and its page on superforge.studio, like
  `Superforge Foundation (https://superforge.studio/foundation)`, by
  `.superforge/superforge.json`'s `template` (`starter-template` is
  Foundation, `premium-template` Skylevel), with no version in it. The
  root route (`source/frontend/routes/__root.tsx`) puts it in every
  page's head, right after `charSet`. A copy whose root route has changed
  adds the one line to its own `meta`, wherever it sets them.
- **Keeping it**, machinery: `CLAUDE.md`, "Keep Superforge's credit in the
  pages' source", the comment at the tag and `template.ts` tell an agent
  to keep the tag through redesigns, renames and cleanups, and, if the
  owner asks for it to go, to tell them it's the one thing Superforge asks
  of a site built on its templates before taking it out.
  `START-HERE.md`'s step 5, which renames the codebase, says to leave it.
- **The smoke test**, machinery: `workbench/scripts/smoke-test.mjs` checks
  the home page and the dashboard each name a Superforge template in
  their `<meta name="generator">`, and fails a build that doesn't, saying
  why.

No flags: no schema, no variable, nothing for the owner to do.

**How to tell a copy already has it**: `source/utilities/template.ts`
exists, and the home page's source has
`<meta name="generator" content="Superforge`.

# 0.37.0 (2026-11-26)

A new copy's setup, rewritten for an owner who starts with nothing but
Claude, and a copy that comes out clean of what only the template has.
`START-HERE.md` is now a short index of four steps, a file each in
`workbench/setup/`: see it run, put the business's name and color on it,
ship it, then make it the business's own. Each file goes once its check
passes. What only the template has is on one list,
`.superforge/template-only`, which a script strips from a new copy and an
update reads its excludes from. A minor, since how a copy is set up and
what an update leaves out both changed. No schema change and no variable.

**Owner**: nothing to decide. A copy that's already set up takes the
guides' changes and two new files (`.claude/settings.json`, `.mcp.json`);
its setup is done, so the new setup files never reach it.

- **`START-HERE.md` is the index**: the four steps, in order, and the rules
  across them. Claude does the first step whose file is still there.
- **`1-see-it.md`**: one question, whether the owner has worked with code,
  written into `CLAUDE.md`'s new "Who you're working with"; pnpm and Node
  installed with no admin password or Homebrew (pnpm's own installer, then
  `pnpm env use --global 22`); the template stripped; the app run.
- **`2-taste.md`**: the business's name, a sentence and one color, on a
  home page of its own, in place of the template's, whose line map goes.
- **`3-ship.md`**: Superforge's project, named, described and written into
  `.superforge/superforge.json`; a private repository made with `gh` (from
  its release, with no Homebrew), with Dependabot's alerts and security
  fixes on; the region and the owner; Railway; the Infra key; the first
  deploy; its domain proven and the owner logged in live; and Railway's
  token last.
- **`4-make-it-theirs.md`**: what was `START-HERE.md`'s steps 1 to 5, the
  interview, the look, the home page and the team, `PRODUCT.md` and
  `DESIGN.md`, the app's own MCP offered as a connector, then the project
  described again, the owner's first wants filed on the board, and the
  setup's files deleted.

## Clean copies (`.superforge/template-only`, `workbench/scripts/strip-template.sh`), machinery

- **One list** names, a line each, what's the template's alone
  (`template`: `SECURITY.md`, `CHANGELOG.md`, `.superforge/releases/`,
  `.github/dependabot.yml`, the list and the script) and what only a copy's
  setup uses (`setup`: `START-HERE.md`, `workbench/setup/`, the welcome
  page and its query).
- **`strip-template.sh`** deletes the `template` lines' paths and every
  Markdown block between `<!-- template-only -->` lines (`README.md`'s
  paragraphs under its title and its "This template"), then the list and
  itself. It needs only bash.
- **An update reads its excludes from the list**, at the release it's
  applying (`workbench/updating.md`, step 4), so a copy never gets one of
  them back, and the release notes are read from the template's tags
  only.
- **A copy keeps no `dependabot.yml`**: each release brings the
  dependencies as tested, and an update takes the release's version of
  each. Security fixes still come, from the repository's settings, which
  `3-ship.md` turns on. CI's `release-version` and `release-tag` stay in
  `ci.yml`, skipped in a copy, so the `main` ruleset needs no change.

## Claude's files (`.claude/settings.json`, `.mcp.json`, `.gitignore`), machinery

- **`.claude/settings.json`** lets Claude run `pnpm`, and git's and `gh`'s
  commands that only read or commit locally, without asking, once the
  folder is trusted.
- **`.mcp.json`** names Superforge's MCP server, `superforge`, so nobody
  types `claude mcp add`.
- **`CLAUDE.local.md`** is ignored, for one person's own words to Claude.
- **`pnpm railway`** runs Railway's CLI at CI's version, with nothing
  installed.

## The guides

`CLAUDE.md`: the first section points at the setup's steps, "Who you're
working with" is new, and "Keep things current" asks for the app's
description on Superforge to be kept up to date. `workbench/updating.md`:
the excludes and the notes, above; a copy made before this release may
delete its own `.superforge/releases/` and `CHANGELOG.md`.
`workbench/commit-and-deploy.md`: Dependabot, `pnpm railway`, and where
the setup's steps are. `README.md`: the start is superforge.studio's.

How to tell a copy already has it: `.mcp.json` names `superforge`, and
`workbench/updating.md`'s step 4 reads `.superforge/template-only`.

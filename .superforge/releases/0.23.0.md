# 0.23.0 (2026-11-24)

The docs and the update guide put right ahead of 1.0.0: a copy starts in
a private repository of its own, an update follows the latest release's
procedure, stops at a release that has to deploy first, and has a rule
for `package.json`, `pnpm check` fails while `schema.ts` has a change no
migration holds, and statements that no longer matched the code are
corrected. A minor, since it changes how an update works and adds a check
that can fail.

## Updating (`workbench/updating.md`), machinery

- **Step 3 reads the latest tag's `workbench/updating.md`, and the update
  follows that one** from step 4 on, so a fix to the procedure works on
  the update that brings it.
- **A Deploy flag**, in "How a release is written": a release that has to
  be deployed before the next is applied. Step 4 stops after it: its PR
  merges and deploys, then the update starts again from step 1. No
  release before this one is flagged Deploy.
- **`package.json` has a rule of its own**: every dependency the template
  lists takes the release's version, the copy's own additions, `name` and
  font stay, then `pnpm install`.
- **What happens when `pnpm database:generate` asks about a rename**, in
  step 4: answer from the notes, never by guessing.
- **Leaves out `source/frontend/queries/health.ts` and `SECURITY.md`**,
  which only the template has. The command in step 4 excludes them.
- The example `superforge.json` is in the order the file has; a wrong
  step is reported as an issue on the template's repository, or privately
  for a security problem.

## The migration check (`workbench/scripts/check-migrations.sh`), machinery

- **A third check: the migrations hold every change to `schema.ts`.** It
  runs `drizzle-kit generate` on a copy of `source/database/migrations/`
  and fails if it would write anything, putting the folder back as it
  was. A changed check, index, default or on-delete without its migration
  used to pass CI and never reach production. Run
  `pnpm database:generate` for it.

## Dependabot (`.github/dependabot.yml`), machinery

- **`@superforge/infra` is never offered**: it moves with the template's
  code that speaks its next release.

## Starting a copy (`START-HERE.md`, `README.md`, `SECURITY.md`), template only

- **Step 0 checks whose repository this is**: a clone of the public
  template stops until the owner has made their own with Use this
  template, private; a copy of their own is checked to be private. The
  README says the same at its top.
- **Step 3 deletes `source/frontend/queries/health.ts`** with the line
  map, the one thing that called it. **Step 5 deletes `SECURITY.md`** and
  takes the template's login address out of the README's "Develop".
- **`SECURITY.md`**, new: a vulnerability in the template is reported
  through GitHub's private vulnerability reporting. The README's "This
  template" says where problems go, and no longer names Superforge's own
  Railway project.

  the template's bullets are never edited in a copy. The jobs' and the

## The code, machinery

- **Unused primitives deleted**: `avatar`, `collapsible`, `command`,
  `input-group`, `separator`, `skeleton`, `slider`, `switch` and
  `tooltip`, which nothing imported, and the `cmdk` dependency only
  `command` used. shadcn adds one back when it's needed
  (`pnpm dlx shadcn@4 add <name>`, `writing-code.md`).
- **`dashboard/words.ts`** takes `MINUTE`, `HOUR` and `DAY` from
  `utilities/primitives/durations.ts` instead of declaring them again.

# 0.36.1 (2026-11-25): the visits' test reads the clock once

`source/backend/visits/tests/record.test.ts`'s "a visit lasts until 30
minutes pass without an event" could fail on no bug. Its events are each
"this long ago", and the file's `event()` helper read the clock for each
one. A busy machine, like CI's runner or a loaded `pnpm check`, lets a
millisecond pass between two of them, and the visit came out a millisecond
longer than the `toBe(10 * MINUTE)` it's checked against. Nothing the app
runs changed.

- **`event()`**, in `source/backend/visits/tests/record.test.ts`,
  machinery: it counts back from one moment per test, `testsNow()`, which
  the test's first event reads, so a test's events are exactly as far
  apart as their `ago`s say however slowly it runs. It's per test rather
  than per file, so "a minute ago" is still a minute before the test that
  made it, whatever ran before it in the file. Under a clock that moves at
  least a millisecond on every read, the test failed every time before
  (`600001` for `600000`) and passes now, and so does every other test in
  the template. Skylevel 0.25.1 fixed its own `pageEvent` the same way.

**A copy with tests of its own** that list a visit's events "this long
ago" and check how long it lasted takes the same care: read the clock
once, and count every event back from that.

**How to tell a copy has it**:
`source/backend/visits/tests/record.test.ts` has `testsNow()`.

# 0.28.1 (2026-11-24)

The login page no longer logs a hydration error for someone logged in.
Opened logged in, `/login` sometimes drew "You're logged in." on its first
render in the browser, over the HTML the prerender drew for a visitor,
"Log in", so React logged "Hydration failed because the server rendered
text didn't match the client" (minified error #418 in a build) and drew
the page again. It happened in the dev server and in the build, on some
loads and not others.

- **Who's logged in, while a page hydrates**, machinery: React hydrates
  the root's part of a page first, and each route's part in a later pass
  of its own, since the root's `<Outlet />` puts a route in a Suspense
  boundary. So the toolbar, in the root, asks `GET /api/auth/session`
  before the page's own part has hydrated, and when the answer came back
  first, `useSession()` (`source/frontend/queries/auth.ts`) read it from
  the cache on the login page's first render and answered `logged-in`.
  It now answers `loading` on any render that hydrates a page, whatever
  the browser knows by then (`useHydrated()`, from
  `@tanstack/react-router`), and who's logged in from the render after.
  So the page hydrates as the visitor's and switches at once, as it
  always did when the answer came later. Whatever's drawn in the browser
  after the page has hydrated, like the admin, or `/login` reached by a
  link, reads who's logged in on its first render, as before. The other
  pages were checked, logged in and logged out, in the dev server and the
  build: the home page and the not-found page don't read the session, and
  the admin and the Allow page draw only in the browser (`ssr: false`),
  so `/login` was the only one. A copy's own component on a public page
  that reads `sessionQuery` with `useQuery`, rather than through
  `useSession()`, has the same race, and reading it through
  `useSession()` ends it.
- **A test**, machinery: `source/frontend/queries/tests/auth.test.ts`
  draws `useSession()` with the session already in the cache, through
  `react-dom/server`, which reads each store's server snapshot as a
  hydrating render does, and expects `loading`.
- **`workbench/writing-code.md`**, machinery: "Where code lives" says a
  prerendered page's first draw in the browser has to be the one the
  prerender made, and how a page reads what only the browser knows.

No flags: no schema, no variable, nothing for the owner to do.

**How to tell a copy already has it**: `useSession()`, in
`source/frontend/queries/auth.ts`, calls `useHydrated()` and answers
`loading` until it's true.

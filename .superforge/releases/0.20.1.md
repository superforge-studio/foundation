# 0.20.1 (2026-11-23)

A column still in `schema.ts` is one the running code uses, even if
nothing reads it: Drizzle names every column a table has in the SQL it
writes. An insert lists them all, with `default` for each one it isn't
given, and `select()` and `.returning()` list them all too. So a column
dropped while the version still serving has it in its `schema.ts` breaks
that version's queries on its table, until the new version starts, about
a minute in a deploy. 0.18.0 kept `users.role` in `schema.ts`, unread, and
0.19.0 dropped it, so the template's own deploy of 0.19.0 failed queries
on `users` (logins and every logged-in request) for that minute. Nothing
in the app changes in this release: it fixes the docs, and how a copy
takes 0.19.0.

- **Dropping a column**, machinery: `workbench/writing-code.md`,
  "Migrations", says the deploy that stops using a column takes it out of
  `schema.ts` and deletes the `DROP COLUMN` that `pnpm database:generate`
  writes, leaving the column (`DROP NOT NULL` in its place, for a column
  that's `NOT NULL` without a default), and the next deploy drops it with
  a migration of its own (`--custom`). A renamed table keeps its old name
  as a view for one deploy.
- **Taking 0.19.0**, for a copy on 0.18.x or earlier that hasn't yet: take
  `role` out of `schema.ts` as 0.19.0 does, but delete `ALTER TABLE
  "users" DROP COLUMN "role";` from the migration it generates, keeping
  the rest (its tables, and `DROP CONSTRAINT "users_role_check"`, which no
  query names). Deploy that. Then drop the column in a deploy of its own:

  ```bash
  pnpm database:generate --custom --name=users-drop-role
  ```

  with this in the file it makes:

  ```sql
  -- Nothing names users.role since the deploy before took it out of
  -- schema.ts
  -- squawk-ignore ban-drop-column
  ALTER TABLE "users" DROP COLUMN "role";
  ```

  A copy that already took 0.19.0 as it was has nothing to do: the column
  is gone, and the minute it failed is over.

**How to tell a copy already has it**: `workbench/writing-code.md`'s
"Migrations" has "A column in `schema.ts` is one the code uses".

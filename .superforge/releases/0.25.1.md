# 0.25.1 (2026-11-24)

Logging out takes the page with it. "Log out of this browser", on Your
account, logged the person out on the server, but the admin went on
drawing them: their email stayed in its bar, and "Your sessions didn't
load" and "Your connections didn't load" showed in red until a refresh.
The login page's Log out showed "Log in", but left the team's toolbar up.

- **Logging out**, machinery: `logOut`, in
  `source/frontend/queries/auth.ts`, removed every query, the session's
  among them, then set the session to no one in a new query. A screen
  watching a query that's removed is never told, so the admin's frame and
  the toolbar kept the person they had, and the account page's lists,
  drawn again as the logout finished, fetched theirs again and were
  answered 401. It now
  sets the session to no one in the query every screen watches, after
  stopping any request for it still on its way, so the admin draws "Log in
  to the admin" at once, the screens behind login go with it, and the
  toolbar goes. Then it removes every other query, as before, with
  whatever was still being fetched, so this browser still forgets
  everything it held for the person, and nothing is asked for as them
  once they've logged out.

No flags: no schema, no variable, nothing for the owner to do.

**How to tell a copy already has it**: `logOut`'s `onSuccess`, in
`source/frontend/queries/auth.ts`, calls `removeQueries` with a
`predicate` that leaves the session's query.

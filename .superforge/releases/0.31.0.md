# 0.31.0 (2026-11-25)

`/api/visits` has a ceiling. It's the one route anyone may write through,
with no login, and it took 64 KB of events a request from anyone, as
often as they liked, for 90 days: a script on one address could fill the
database for the price of a `curl` loop. And since a visitor's ID is
whatever their cookie says, a script that kept sending to one ID grew one
visit forever, each batch costing more than the last to work out again,
until the database's connections were all waiting on it. Now each
network has a day's allowance, and a visit holds at most 5,000 events. A
minor, since the route can answer 429. No flags: no schema change, no
variable, nothing for the owner to do.

## A network's day (`source/backend/visits/limit.ts`, `source/backend/visits/routes.ts`), machinery

- **Each batch is counted against its network's day before anything is
  kept**: 20,000 a day (`PAGE_EVENTS_A_DAY`), a day from the network's
  first batch, each batch counting as its events, or as its kilobytes
  when that's more (`batchCost`), by the network as login counts it
  (`networkKey`: an IPv4 address, an IPv6 address's /64).
- **The team's batches, logged in, and a bot's aren't counted.** So an
  office of the business's own, using the admin all day, never meets it.
- **Past it, the batch is 429 `too-many`**, with a `Retry-After` and
  `retry_after`, and nothing of it is kept. The page's script drops it, as
  it drops any 4xx, so the visitor sees nothing. The batch that takes a
  network past is logged once: `A network sent more page events than a
  day allows, so the rest of its day's are refused`, with nothing of who
  sent it.
- **`isBot(user_agent)`** (`browsers.ts`) is the bot check
  `describeBrowser` makes, on its own.

A day is hundreds of visits from one address. A copy whose visitors
mostly share one, like a campus café's, raises `PAGE_EVENTS_A_DAY`.

## A visit's most (`source/backend/visits/record.ts`), machinery

**A visit holds at most 5,000 events** (`EVENTS_A_VISIT`): the next starts
a new visit, as a 30-minute gap does. `recordVisit` counts what the
visitor's latest visit holds, no further than 5,000, before it sorts a
batch's events into visits. A visitor would need an event every six
seconds for eight hours without a break to reach it; a script sending to
one ID from many addresses now costs at most that with each batch.

## The limiter's amount (`source/backend/rate-limits/count.ts`), machinery

- **`countAttempt` takes an `amount`**, one unless it says, for an attempt
  that counts as more than one, like a batch of events.
- **A refusal says the count** beside `retry_after`, so a caller can tell
  the attempt that went past from the ones after it.

A copy whose own code calls `countAttempt` needs nothing: both are
additions.

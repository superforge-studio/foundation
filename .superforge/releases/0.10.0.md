# 0.10.0 (2026-11-22)

What's trying to reach the app and can't is in its logs. Until now a
request no route or page answered was answered 404 and forgotten, and a
POST to a page's address was drawn as the page and answered 200, so a
webhook set up with the wrong address looked delivered to whatever sent
it, and nobody knew it never arrived.

- **Every miss and every failure, logged**, machinery:
  `source/backend/misses/`, new. `log.ts`'s `logMiss` logs a request
  nothing answers, and `logFailure` one answered 500 or more, each on one
  line, its facts as JSON beside a static message (method, host, path,
  user agent, referrer, body type and size, and the names of any
  signature headers, never a query string or a header's value).
  `sort.ts` drops what scanners try on every site (`.php`, `/wp-*`,
  `/.env`, `/.git`, unless it's signed like a webhook) and makes a miss a
  warning, `A request missed that looks meant for the app`, with its
  `because`, when it carries a webhook's signature header, sends JSON, is
  under `/api`, or came from one of the site's own pages. The rest are
  `A request missed`, information, and failures `A request failed`, an
  error. `source/server.ts` logs what every handler answers, wrapping
  them as `answer`, and `backend/failures.ts`'s `answerNotFound` logs the
  API's own misses, since the API's routes answer 404 too, for what isn't
  there. `workbench/writing-code.md`, "Logging", has how to read them. A
  copy whose `server.ts` has paths of its own keeps them inside `answer`.
- **A page takes only `GET` and `HEAD`**, machinery, and a change to how
  something works: anything else sent where a page would be is answered
  405 (`source/server.ts`, `refuseForPage`), and logged, before it
  reaches Start. A copy with a TanStack Start server function or server
  route, which the headless rule already forbids, moves it under `/api`
  first, or its POSTs are refused. The smoke test checks a POST to `/`
  answers 405.
- **The version's three numbers, named**, machinery:
  `workbench/updating.md`'s "How a release is written" says what moves
  each of `major.minor.patch`: a patch only fixes, a minor adds or
  changes, and the major stays `0` until `1.0.0`.

How to tell a copy already has it: `source/backend/misses/log.ts`.

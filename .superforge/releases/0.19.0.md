# 0.19.0 (2026-11-23)

The team's own files, kept in the bucket in folders, with an API to
upload, sort, share and delete them, but no screen yet. A limiter any
route anyone may call can count by network. And `users.role` is dropped,
as 0.18.0 said the next release would. Files and the limiter come from
Skylevel, which has had both since its first releases, in the same shape,
so Skylevel stays Foundation with more on top.

**Deploy 0.18.0 before this one.** This release drops `users.role`, which
a version before 0.18.0 still reads. A copy on 0.17.0 or earlier takes
0.18.0, deploys it, and only then takes this one, in a deploy of its own.

- **Your files**, machinery. **Schema**: `file_folders` (a folder, in
  another or at the top, who made it, and when it went to Trash) and
  `files` (its folder, name, type, size, whether its bytes are in yet,
  `uploading` then `ready`, who uploaded it, and when it went to Trash),
  in `public`, in `source/database/schema.ts`. A file's bytes are in the
  bucket under `files/<file id>`, never its name, so a rename or a move
  changes a row and nothing in the bucket. `Storage` gains the `files`
  kind, the only one that's open, and `unclaimed()`, the bucket's top
  folders no kind claims (`source/database/storage/files.ts`).
  `source/backend/files/` answers under `/api/files`: a folder's contents
  (`GET /files/folders/:folder_id`, `root` for the top), folders made,
  renamed, moved, taken to Trash and brought back, an upload started on a
  form presigned for the bucket (`POST /files/uploads`), its bytes taken
  by the server in a dev server, whose folder can't sign
  (`PUT /files/uploads/:file_id`), and finished
  (`POST /files/uploads/:file_id/done`), a file downloaded on a
  five-minute link or shared on a week's (`POST /files/:file_id/link`),
  renamed, moved, taken to Trash and brought back, Trash itself, deleted
  for good after 30 days, and the folders the app keeps for itself,
  listed and downloaded by the paths their listing gives
  (`/files/kept/:folder`), never changed. Its limits are in
  `source/utilities/schemas/files.ts`: 100 MB a file, 30 days in Trash, a
  week for a link. `send.ts`'s `requestedRange` reads a `Range` header,
  so a dev server streams a file a range at a time. No screen draws any
  of it: a script or an agent uses the API, and a copy that wants a Files
  screen builds it on these routes. A browser posting straight to the
  bucket also needs the bucket's CORS, which this release doesn't set:
  Skylevel's `source/database/storage/cors.ts` is how.
- **The `files` area**, machinery. Every files route is
  `permitted("files")`: `files` joins `AREA_NAMES` and `AREAS` in
  `source/utilities/permissions.ts`. An `owner` has it already. In
  `source/backend/auth/access.ts`, the template's `member` is given
  `files: "write"`, beside what it had. `roles` is the copy's own
  (START-HERE.md sets it), so the update adds the line only where the
  copy's `member` is still the template's; a copy that changed it asks
  the owner what a member may do with files, `none` until they say.
- **The rate limiter**, machinery. **Schema**: `internal.rate_limits`, a
  count over a window by what's limited (`bucket`) and a hash of who did
  it (`key`). `source/backend/rate-limits/count.ts`'s `countAttempt`
  counts one more and refuses past the most it's given, with how many
  seconds until the window ends, and `networkKey(ip)` hashes a caller's
  network as `visits/visitors.ts` counts one (an IPv6 address's /64).
  Nothing in the template calls it yet; `workbench/writing-code.md` says
  when a route should.
- **`users.role` dropped**, machinery. **Schema**: the column and its
  check, `users_role_check`, go. Nothing has read or written it since
  0.18.0.
- **The sample files**, machinery. `source/database/seed/files.ts` makes
  folders, files of several types, an upload never finished, and a folder
  and a file in Trash, and `pnpm database:seed` keeps their bytes in the
  checkout's `.storage/`. `internal.rate_limits` is in `UNSEEDED`.
- **How tables are named**, machinery. `schema.ts`'s header and
  `workbench/writing-code.md` word it as Skylevel does: a table that is
  the thing itself is named for it (`files`); any other starts with what
  it's about, then what its rows are (`file_folders`); and a name never
  repeats its Postgres schema (`auth.sessions`).
- **The docs**, machinery. `CLAUDE.md` lists `files/` and `rate-limits/`,
  the tables and the bucket's kinds, and `workbench/writing-code.md`
  says where a route anyone may call counts its attempts and where a file
  goes.

**How to tell a copy already has it**: `source/database/schema.ts` exports
`files`, `file_folders` and `rate_limits`, and `users` has no `role`;
`source/backend/rate-limits/count.ts` exists.
